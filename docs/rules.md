# Rules

The rules are data: each has an id, a severity, a plain explanation and MITRE ATT&CK IDs. The full list, with the exact matching logic, is in [`src/rules/rules.ts`](../src/rules/rules.ts), and every finding also states in the app which trigger it matched. Summary:

| id | Severity | What it catches |
|---|---|---|
| `fake-prompt` | high | `osascript` whose arguments contain `display dialog` (or JavaScript for Automation's `displayDialog`) or `hidden answer`: a fake system password prompt (T1056.002). |
| `osascript-script` | med | `osascript` running a script file from a temporary, Downloads, shared, hidden, mounted-volume or translocated location, or reading its script from a pipe with no file on disk (T1059.002, or T1059.007 with `-l JavaScript`). |
| `keychain-access` | high, med or low | `security` against the keychain. High: `find-generic-password` or `find-internet-password` with `-g` or `-w` for a browser's or app's “Safe Storage” key or a crypto wallet entry, or `dump-keychain -d`. Med: any other `find-*-password -g` or `-w`. Low, context only: attribute lookups, `unlock-keychain`, `export`, `dump-keychain` without `-d` (T1555.001). |
| `security-setting-change` | high or med | Commands that weaken a protection or redirect traffic. High: `spctl --master-disable`, `--global-disable`, `--disable` naming no rule, `--add` (T1562.001, T1553.001); `csrutil disable`, `csrutil authenticated-root disable`, `csrutil enable --without` (T1562.001); `security add-trusted-cert` that trusts a root (T1553.004). Med: `spctl --disable` naming a rule; `add-trusted-cert -r deny` or `-r unspecified` (T1553); `security authorizationdb write` (T1548); `networksetup` setting a web, secure web, automatic, SOCKS proxy or DNS servers, or turning a proxy on (T1557). The text says when the command only works on older macOS or from Recovery, so it may be an attempt. |
| `dscl-authonly` | high | `dscl ... -authonly` (or `authonly`): verifying a password the attacker just phished with a fake prompt (T1056.002). |
| `persistence-item` | high or med | A launch item registered with the background task manager (`btm_launch_item_add`). High if it runs a shell or interpreter (python, perl, ruby, osascript, node, php), runs from a place a user process can write to (a temporary folder, `/Users/Shared`, Downloads, a mounted volume, a hidden or dot-folder, `~/Library/Caches`), ran unsigned or ad-hoc signed in this capture, or is a loose program (not an app bundle) anywhere in a home folder. Also high when the plist is named `com.apple.…` (in a user's `~/Library/LaunchAgents`, `/Library/LaunchAgents` or `/Library/LaunchDaemons`) but the item runs something outside Apple's folders (`/System`, `/usr` except `/usr/local`, `/bin`, `/sbin`, `/Library/Apple`) that the capture does not show to be Apple's own: a platform binary, or a real `com.apple.*` signature from one of Apple's team IDs (a self-signed `com.apple.*` image with no team ID does not count, wherever it sits). Med otherwise, for example a per-user updater app in `~/Library`, or anything under `/Applications` or a system folder. The evidence says which reason applied. MITRE follows the item type: launch agent T1543.001, launch daemon T1543.004, login item, app or user item T1547.015. |
| `persistence-plist` | high | A process (one that exec'd, or one that only forked) wrote or renamed a `.plist` into a `LaunchAgents` folder (`~/Library`, `/Library`) or `/Library/LaunchDaemons`, or modified one there in place (a `write` event, or a `close` event marked modified; seen only when the capture records one of them), and no registration event attaches its finding to that same process (T1543.001 or T1543.004, by folder). |
| `launchctl-load` | high | `launchctl load`, `bootstrap` or `submit`: starting a launch job right now (T1569.001). |
| `quarantine-strip` | high | `xattr -c` (also in clusters such as `-cr`), or `xattr -d com.apple.quarantine`: removing the flag that makes Gatekeeper check a download (T1553.001). |
| `timestomp` | high or low | `touch` with `-r`, `-t`, `-d` or `-A`, or `SetFile` with `-d` or `-m`: setting a file's dates by hand. The targets are the file arguments (relative ones resolved against the working directory); the `-r` reference file is not a target, and the evidence names it, since it shows which legitimate item the file was made to look like. High when a target is a launch plist (`~/Library/LaunchAgents`, `/Library/LaunchAgents`, `/Library/LaunchDaemons`), a program that ran in the capture, or a file in a strong odd place other than a temporary folder (`/Users/Shared`, Downloads, a mounted volume, a translocated app, a hidden folder). Low, context only, otherwise: builds set dates for reproducible output, and source builds (Homebrew, pip) do it inside `/tmp` and `/var/folders`. A program that sets dates through the system API leaves no trace in a capture: `touch` itself reaches the kernel as `setattrlist`, which says which attributes changed but not the new dates (T1070.006). |
| `payload-decode` | med | `openssl ... -d` (but not the digest commands such as `dgst`, where `-d` is debug), or `base64 -d`: unpacking a hidden payload (T1140). |
| `shell-from-pipe` | med | stdin is a pipe and no script file runs: a shell with no arguments or `-s` and no `-c`, or `python`, `perl` or `ruby` with no inline code and no script: the `curl ... \| bash` pattern, with no script on disk to inspect. `--version`/`--help` and similar probes do not count, but a ruby `-v` probe followed by `-` still reads the piped script. Needs `eslogger` schema 11 (T1059.004, T1059.006 for Python, T1059 for Perl and Ruby). |
| `reverse-shell` | high or med | A shell or interpreter wired to a network connection. Two ways to see it. A shell (`sh`, `bash`, `zsh` and the others) or `python`, `perl` or `ruby` reading its commands from a socket (no `-c`, no inline code, no script; `-i` allowed): high, or med when `sshd` or `sshd-session` is among its ancestors, since an `ssh -T` session also hands its shell a socket. Programs that only get a socket as stdin, such as `git` started by Node or Electron, do not count. Or a command line that sets one up, always high: a shell `-c` script that ties its own input or output to `/dev/tcp/` or `/dev/udp/` (`>&`, `&>`, `<&`, a redirection plus `0>&1`, or `exec N<>` whose descriptor a shell then reads), but not a bare port check such as `</dev/tcp/db/5432` or `exec 3<>/dev/tcp/db/5432`, nor an HTTP request sent through one; `ncat` or `netcat` with `-e`, `-c`, `--exec` or `--sh-exec`, and `nc -e` (Apple's `nc -c` only sends CRLF); `socat` with an `exec:` or `system:` address; a fifo with `nc` and a shell as commands in the same script; a `python`, `perl`, `ruby` or `php` one-liner (`-c`, `-e` or `-r`, attached or not) that connects a socket (`connect(`, `create_connection`, `TCPSocket`, `IO::Socket`, `fsockopen`) and hands it to a shell (`dup2`, `fileno`, `pty.spawn`, `open(STDIN`, `<&N`, `/bin/sh`); zsh's `ztcp`. Matching is on these words, never on the host, so a cleaned capture gives the same findings. The socket check needs `eslogger` schema 11 (T1059.004, T1059.006 for Python, T1059 for Perl, Ruby and PHP, T1095). |
| `clickfix-paste-chain` | high | A shell, interpreter or `osascript` reading commands from a pipe within 3 s of a sibling (same parent) that decodes (`base64 -d`, `openssl enc -d`, `xxd -r`) or fetches with `curl`/`nscurl` `-k` or `-A`, or `wget --no-check-certificate`: the line a ClickFix page tells the user to paste. Plain `curl … \| bash` stays at `shell-from-pipe`; a snapshot shell started by the AI coding agent itself (Claude Code or Codex; not Cursor, whose helpers also run a workspace's own tasks) is ignored, judged by the agent being its parent, never by text in its command (T1204.004, T1059.004, T1140, T1105). |
| `shell-under-app` | med | A shell launched, when it was born, by an app inside a `.app` bundle other than terminals and editors (T1059.004). |
| `risky-parent-spawn` | high | A parent that should not run commands ran one, seen at the child's birth: Script Editor, an AppleScript applet or an Automator stub running a shell, `curl`, `osascript`, `python`, `chmod` and similar; Word, Excel or PowerPoint (or a process they are responsible for) running a shell, `python`, `perl`, `ruby`, `osascript`, `curl` or `chmod`, but not Microsoft AutoUpdate as Microsoft signed it; or VS Code, Cursor, Windsurf, Xcode, `dotnet`, `node` or `bun` running `osascript` or a shell `-c` that fetches with `curl`/`wget` and also uses `nohup`, a pipe into an interpreter, `curl -k` or `wget --no-check-certificate`. npm-installed AI coding agents (node or bun running Claude Code, Gemini CLI or Codex) and a Claude Code or Codex snapshot shell under that agent are ignored; Cursor's agent shells are not; `shell-under-app` may also fire (T1059.002, T1059.004, T1204.002). |
| `download` | med | `curl` writing to a file (`-o`/`--output`, `-O`/`--remote-name`), `wget` with a URL (it saves a file by default, unless `-O` points at `-` or `/dev/null`; `-o` is only the log), or either one that created a file (T1105). |
| `dropped-then-executed` | med or high | A program ran at most 15 s after a process created it or renamed it into place, from a strong odd place or under a hidden name in a home folder (outside build and tooling folders): the `curl -o` then run pattern. High if the file is unsigned or ad-hoc signed, has a hidden name, or was deleted within 60 s of running; med otherwise. Compilers, linkers and build tools as the writer (unless it is unsigned or runs from a strong odd place), Go's build folders, and installers writing to `/Applications` are not flagged (T1105, T1204.002, T1070.004 for the delete, T1564.001 for a hidden name). |
| `credential-store-copy` | med or high | A process created (or renamed into place) a credential store in a temporary, Downloads, shared or hidden folder, or ran `cp`, `ditto`, `rsync`, `scp`, `zip`, `tar`, `sqlite3` or `cat` with one among its arguments. Credential stores: the login keychain and anything in a `Library/Keychains` folder, a browser's `Login Data`, `Cookies`, `Web Data`, `Local State`, `Cookies.binarycookies` or `Local Extension Settings`, Firefox's `key4.db`, `logins.json` and `cookies.sqlite`, and the Notes database (`NoteStore.sqlite`). A file created in a browser's own profile folder, on a mounted volume or in a dot-folder directly in home, or by a browser engine itself (Chrome, Edge, Brave, Firefox, Arc, Vivaldi, Opera, headless builds: browser automation uses a temporary profile), is not flagged. High if the program is unsigned, ad-hoc signed or runs from a strong odd place, or if a copy tool also names a staging place; med otherwise. Backup tools and Migration Assistant do this legitimately (T1555.001 for keychains, T1555.003 for browsers, T1005, T1074.001 for staging). |
| `mass-rename` | high | One process renamed 10 or more files to the same new extension within 10 seconds: how ransomware marks the files it has encrypted in place (T1486). Only files that already existed and are renamed in their own folder count: a temporary file the process created itself and then renamed or moved (`tmp.x7Hd2` to `icon.car`, `name.plist.a1B2c3` to `name.plist`, anything to or from `.tmp`, `.part`, `.download`, `.crdownload`, `.swp`, `.bak`, `.partial`) and renames that keep the extension are ignored; this needs the capture to include `create` events. A capture cleaned with `ficus-clean` keeps only common file extensions, so a ransom extension such as `.heartbreaker` is replaced along with the name and the rule cannot fire on the cleaned copy. The thresholds come from one sample. |
| `file-upload` | high or med | `curl` or `wget` sending a local file to a server: `-T`/`--upload-file`, `-F name=@file`, `-d`/`--data`/`--data-binary`/`--json @file`, `--data-urlencode @file`, wget `--post-file`/`--body-file` (T1041). High when the file is in a temporary, Downloads or buried hidden folder (a relative name counts through the working directory), or is an archive, or the server is a bare IP address; med otherwise. A server on this Mac (localhost, 127.x, ::1) and `@-` (standard input) are ignored. |
| `archive-staging` | med or high | `ditto -c`, `zip`, or `tar` in create mode. High if a path it names is in a temporary, Downloads, shared, volume, translocated or hidden location; med otherwise (T1560.001). |
| `odd-location-exec` | high, med or low | A program or its script run from a place a normal install does not run from. Strong places: `/tmp`, `/var/tmp`, `/var/folders`, `/Users/Shared`, `~/Downloads`, `/Volumes`, App Translocation, and a hidden folder below a visible one in a home folder. For a program there: high if unsigned or ad-hoc signed, med if signed without a team ID, low if team-signed; a script there is med. Weak places: a dot-folder directly in home (`~/.cargo`, `~/.local`), a hidden folder inside a project build or tooling folder (`.git`, `node_modules`, `.build`, `.terraform`, `.venv`, `target`, ...), Go's build folder: med if unsigned, else low. Low findings are context only (T1204.002). |
| `known-indicator` | high or med | A program, a file it created or moved into place, or a command line matches an indicator that vendors published for a named family: a code-signing team or signing ID, a file, folder or launch-plist path, or a word in a command line (ChillyHell, KANDYKORN, RustBucket, FlexibleFerret, the Contagious Interview kit, an Evasive Panda downloader, MACMA, GIMMICK, DazzleSpy and others). The list is [`src/rules/indicators.json`](../src/rules/indicators.json), each entry with its source and confidence; high only for a high-confidence, distinctive indicator. A launch-plist match cites T1543.001 or T1543.004. A match is evidence, not behaviour: names change between samples, so a miss proves nothing. Hashes and network indicators are not in the list, since a capture holds neither. |
| `unsigned` | med | A non-Apple binary with no code signature at all. A trait of the binary, not a technique, so it cites no MITRE ID. |
| `apple-masquerade` | high or med | Code wearing an Apple name it does not have. Two forms: a program that is not a platform binary but carries a `com.apple.…` signing ID, ad-hoc signed or under another team's certificate (a signing ID is the signer's own choice); or a program that is not Apple's (Apple's own code is a platform binary, or a `com.apple.*` signing ID with a real signature and one of Apple's team IDs (Xcode, iWork and similar apps; the list is built in, so an Apple app signed by a team not on it would be flagged), or with no team ID and a path only Apple writes to: `/System`, `/usr` but not `/usr/local`, `/Library/Apple`, `/Library/Developer`, `/Applications/Xcode*.app`. A self-signed certificate has no team ID, and a `com.apple.*` ID under any other team's certificate is a spoof, never trusted) creating or renaming into place a `com.apple.…` plist (hidden `.com.apple.…` too) in `~/Library/LaunchAgents`, `/Library/LaunchAgents` or `/Library/LaunchDaemons`. A signing ID alone is high; a plist is high in a user's `~/Library/LaunchAgents` or when the writer is unsigned or ad-hoc, med otherwise. Apple's installers write these plists legitimately and are never flagged, but in a user's `~/Library/LaunchAgents` even a platform `cp`, `tee`, shell, `osascript`, interpreter or `curl` counts as a non-Apple writer (T1036.005, T1543.001 for agents, T1543.004 for daemons). |
| `adhoc` | low | A non-Apple binary that is ad-hoc signed, so it has no developer identity. Common for Homebrew and locally built tools, so it is context only. Also a trait. |
| `orphaned` | low | A process whose parent exited so it now sits under launchd (pid 1), though it was started by something else (not `xpcproxy`): the double fork that detaches a daemon (T1036.009). |
| `uid-mismatch` | high, med or low | A process whose own effective user or group id differs from its real one. Climbing: a user's process running with root's (or another account's) privileges, from a setuid or setgid binary or a `setuid()` call. High for a non-Apple binary (including a copy that only borrows an Apple signing ID); med for an Apple platform binary that is not a known setuid tool; low for Apple's own setuid tools (`ps`, `sudo`, `su`, `crontab` and others). Dropping: a root process running with a user's effective id (`loginwindow`, or a vendor daemon acting for the logged-in user) gave its privileges up and can take them back, and so did one whose real group is wheel but whose effective group is another; always low, titled "Dropped privileges". A process whose real and effective user is root and only has another effective group already holds every privilege; always low, titled "Root with another effective group". Each image the process ran is judged on its own and the worst counts. Low is context only unless the process is in a flagged chain (T1548.001). |
| `recon` | low | `ps` (T1057); `networksetup`, `scutil` (T1016); `airport` (T1016.002); `csrutil`, `spctl` (T1518.001); `whoami`, `id` (T1033); `system_profiler`, `sw_vers`, `sysctl`, `ioreg`, `uname`, `hostname`, `scutil --get` (T1082). Forms that change a setting are not recon. Queued only in a flagged chain or a recon burst; otherwise shown as context in the detail pane (see [What the queue means](triage-queue.md)). |
